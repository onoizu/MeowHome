# 测试记录与复现步骤

最近复核日期：2026-11-02。环境：Node.js 25.5.0、SQLite、Chrome，桌面 1440px 和手机 360px。自动测试使用临时数据库，不向日常数据库加入账号。

## 自动 API 测试

在 `source/` 执行 `npm test`。测试只依赖 Node 内置测试工具，自动建立临时数据库和 HTTP 服务，结束后清理。已通过 9 组子测试（连同外层流程共 10 项）：

1. 空数据库、注册、重复电邮、错误密码、HttpOnly cookie、密码哈希。
2. 发布、图片类型检查、编辑、非主人操作被拒绝、交接前不能写日记。
3. 提交与编辑申请、禁止自申请和重复申请、第三方不能读取或处理申请。
4. 两份申请竞争接受时只有一份成功；取消接受重新开放；交接后关闭其他待处理申请，记录不可重复完成。
5. 日记创建、私密隔离、公开、编辑及作者权限。
6. 资料修改、收藏、清单、跨站写请求限制和符合条件的账号删除。
7. 重启服务后账号、Session、猫咪、日记、收藏及清单仍可读取；退出后 Session 无效。
8. 撤回与删除申请、删除无有效申请的猫咪，以及外键一致性检查。
9. 居住状况和匹配原因为选填；省略、短文本、清空可保存，超过长度上限被拒绝。

## 浏览器流程检查

已用独立 Chrome 会话、临时数据库和两个实际注册账号进行操作；以下步骤可手动复现。

- **T01 空状态**：新数据库打开首页、广场和故事页。预期无预设猫咪或故事，空状态正常。
- **T02 注册**：填写姓名、电邮和两次密码。预期注册成功、进入个人中心；重复电邮或两次密码不一致时显示错误。
- **T03 发布**：账号 A 填三步送养表单并上传图片。预期创建数据库记录、图片文件，广场立即可见；编辑后详情同步更新。
- **T04 收藏**：账号 B 收藏 A 的猫咪。预期个人中心可读，刷新仍在，A 不共享 B 的收藏。
- **T05 申请**：B 提交并修改申请的居住环境。预期 A 的收到申请区读取到更新，B 无重复有效申请。
- **T06 接受**：A 接受 B。预期猫咪变为 reserved，新申请被拒绝；B 可以查看送养者联系电邮。
- **T07 交接**：A 确认交接。预期猫咪 adopted、B 的申请 completed；B 获得对应日记创建资格。
- **T08 日记隐私**：B 新建私密日记。预期 A/访客故事列表没有该记录；B 编辑为公开后可见，再删除后消失。
- **T09 清单**：B 勾选准备清单并刷新。预期勾选状态从数据库恢复。
- **T10 资料与登录**：修改显示名后刷新，退出并重新用密码登录。预期资料正确，导航登录状态正确。
- **T11 响应式**：9 个页面在 360px 检查。预期无横向溢出，手机导航和筛选可展开。
- **T12 浏览器错误**：检查 Console 与网络请求。英文和繁体界面均完成全流程，未发现未处理的脚本错误或静态资源缺失。尝试删除关联领养历史的账号时，API 按预期返回 409，并在页面显示原因。

- **T13 公开展示状态**：已用临时数据库验证：英文及繁体详情页不显示“待领养”标签；未审核申请不影响公开展示；接受后从首页和广场隐藏；撤回已接受申请后恢复；完成交接后继续隐藏并保留历史。旧的 `status=reserved/adopted` URL 不会让非待领养猫咪重新出现在广场。

另外建议提交前由两位成员各自重新执行：接受后由申请人撤回；直接拒绝申请；删除终止申请；删除无有效申请的发布；注册一个没有关联数据的账号后删除账号。对应服务端路径已纳入 API 测试。

## 已知范围

- 不测试真实邮件发送、即时聊天或管理员审核，这些未实现。
- 每次页面载入和写操作后读取服务器数据，不包含实时推送或离线写入。
- 已完成领养相关的账号、发布和申请不能删除，以保留数据关系。
- 图片通过类型、大小和文件签名检查，不进行病毒扫描；不自动清理旧上传文件。
